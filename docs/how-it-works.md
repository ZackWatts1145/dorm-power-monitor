# 原理说明

## 数据从哪来

宁夏理工学院「缴费平台」小程序（`jxpt.nxist.com`）背后是一套普通的 HTTP 接口。小程序自己也是调这些接口拿数据的，本项目复用的就是其中两个只读接口：

| 用途 | 接口 |
|---|---|
| 按房间号查房间 | `GET /api/v1/electricity/WeChat/login/findRoomListPage?roomCode=&page=1&size=20` |
| 查剩余电量金额 | `GET /api/v1/electricity/phone/onePassPreChargeSelect?roomId=&roomCode=&type=0` |

返回大致长这样：

```json
{
  "code": 2000,
  "msg": "success",
  "data": { "energy": 5.4, "money": 2.70, "meterId": 161, "reportStatus": 0 }
}
```

- `energy`：剩余电量，单位度（kWh）
- `money`：剩余金额，单位元
- `reportStatus`：0 正常；1 表示电表查询超时
- `code`：2000/200 表示成功；5000 表示设备离线

这两个接口**不需要登录、不需要 cookie、不需要签名**，只要房间号对就行。所以整个方案不需要碰微信登录态，也不需要在手机上装任何东西。

## 一次巡检做了什么

```
读 config.json
  └─ 如果没缓存 roomId：先用房间号换 roomId、楼栋名（只做一次，之后存 state.json）
      └─ 查一次电量金额
          ├─ 写一行到 history.csv
          ├─ 和阈值比较
          │   ├─ 没超 → 记日志，退出 0
          │   └─ 超了 → 看冷却时间 → 发微信 → 记 last_alert
          └─ 查询失败 → 失败计数 +1，连续 3 次发「掉线告警」
```

几个细节：

- **冷却**：默认 12 小时内同一状态不重复推送，避免刷屏。
- **充值重置**：如果检测到电量比上次涨了 1 度以上，认为充过值，清空冷却，这样下次跌破阈值能立刻提醒。
- **趋势**：`history.csv` 攒够样本后，会按最近一段单调下降的数据算日均消耗，附在消息里告诉你还能用几天。中途充过值会自动从充值后的那段重算。
- **自愈**：房间号对应的 roomId 变了（比如换宿舍楼），改 config 里的房间号即可；`--resolve` 可以强制重新解析。

## 为什么不做成中心服务

一个中心服务替所有人轮询，就需要有人长期维护服务器、承担费用，而且所有房间的查询都从一个 IP 发出，容易被判定为异常流量。

分发成「每人自己跑一份」之后：

- 每个实例只查自己那一个房间，30 分钟一次，跟人手动点开小程序看一次没区别；
- 不需要中心服务器，用 GitHub Actions 的免费额度就够；
- 谁的 key 谁自己管，互相看不到对方的推送。

## 关于接口的性质

这套接口是学校系统的一部分，不属于本项目。它目前没有鉴权，这本身是个安全问题，但不代表可以随便用：

- 只查自己的房间；
- 不要提高频率（30 分钟已经足够）；
- 不要拿它做公开查询工具或批量采集。

接口随时可能变更、加鉴权或下线，本项目不保证长期可用。

接口是通过分析小程序前端调用得到的。这里只记录调用方式，不提供小程序包解密、抓包等过程说明——那部分与本项目的使用无关，也不适合公开传播。
